# PAIN recreation: methodology and claims

This document explains the pipeline stage by stage and states, at each stage, what the recreation claims and at what grade.
It replaces `CLAIMS.md`. The evidence and pass criteria are in [`VALIDATION_GUIDELINE.md`](VALIDATION_GUIDELINE.md), the build
order is in [`IMPLEMENTATION_PLAN.md`](IMPLEMENTATION_PLAN.md), and the diagrams are in [`flowchart.md`](flowchart.md).
The layout each pipeline chunk follows (name, function, inputs and outputs, sources, cases with criteria) is in
[`METHODOLOGY_STRUCTURE.md`](METHODOLOGY_STRUCTURE.md); §2.3 is the first chunk written that way.

## Grades used for every claim

| Grade | Meaning | What it allows you to say |
|-------|---------|---------------------------|
| **V-EXP** | Compared with measurement the parameters were not fitted to | "Agrees with the measured data within the stated tolerance" |
| **calibrated (in-sample)** | Parameters were set against the same figures the result is compared to, and no held-out subset is documented | "Consistent with these figures." A goodness-of-fit, not a validation |
| **V-EXP, calibrated** | Inputs were scaled to measurement, but the compared quantity was held out (the Report 996 scaled-load runs) | "Agrees within X dB given the scaled inputs" |
| **V-CODE** | Reproduces a NASA code table (C-1, D-1) | "Matches the reference table." Not experimental proof |
| **V-UNIT** | Matches a written equation | "Implements the equation" |
| **V-ASSUMED** | Physics the papers do not fix | Must be labelled assumed; unit tests verify code, not physics |
| **X-EXTRAP** | The aircraft application, or CCBlade/F1A outside the cases it is checked against | An extrapolation, with no NASA validation inherited |

**Which checks carry a verdict (rule 2026-10-29, Phase 82).** Only a comparison with measurement (V-EXP) or a reproduction of what PAIN printed from PAIN's own inputs (V-CODE against NASA's PAIN outputs) carries a met / not-met verdict on the validation map. Checks against analytic limits, laws, other methods or reports, or properties of printed tables are verification (V-UNIT): information cases or unit tests. ## 1. The pipeline at a glance

Propeller noise at the fuselage skin -> blocking by the fuselage -> cabin and structural modes -> interior SPL -> dB(A), SIL.

| Stage | What it does | Grade today | Detail |
|-------|--------------|-------------|--------|
| 1a. Free field, NASA measured data (validation test only, not a user option) | Digitized Fig. E-11 line, extended to 160 points by GEXT, used only to test the cabin model | Input V-EXP (repeatability only); GEXT V-ASSUMED | [§2.2](#22-nasa-measured-path-e11) |
| 1b. Free field, BEMT + F1A (the only user option) | CCBlade loads -> AcousticAnalogies F1A at the observers | X-EXTRAP | [§2.3](#23-airfoil-bemtf1a) |
| 2. Blocking (Eq. 43) | Raises the free-field pressure for reflection at the fuselage | V-UNIT / V-CODE | [§3](#3-stage-2--blocking-eq-43) |
| 3. Cabin acoustic modes (CYL2D) | 2-D finite-difference cross-section eigensolver | V-CODE | [§4](#4-stage-3--cabin-acoustic-modes-cyl2d) |
| 4. Structural modes (MRP) | Rayleigh-Ritz shell and floor modes | Hybrid transcription (`no_verdict`); raw solver calibrated (26/32 live) | [§5](#5-stage-4--structural-modes-mrp) |
| 5. PAIN core | Coupling, generalized force, trim, loss, power balance, reverberant NR (Eq. 18), HF tone Eqs. (15)–(16), high-frequency broadband Eqs. (19)–(23) | T1/T2 recorded; E-21/E-22 NR (38a); HF tones (38b); printed HF broadband (38c) `T2_EQ19` first run not met; `E18_TONES` (38d) 2/3 not met; `E15_STRUCT_LOSS` (38e) η_r′ info; default T2 still surrogate/`bb_j2_scale` | [§6](#6-stage-5--pain-core-and-the-end-to-end-tests) |

The NASA measured line is a validation test input, not a user option: it exists only to check stages 2–5 against NASA's published results. The cabin stages are the same in both cases. The diagrams are `flowchart.md` diagram 2 (NASA validation), diagram 3 (aircraft

## 2. Stage 1: free-field source at the 160 skin points

PAIN needs the free-field pressure amplitude and phase, per harmonic, at 160 points on the fuselage skin (the interface is
`VALIDATION_GUIDELINE.md` §5). Phases pass through blocking unchanged, and the generalized force uses the phase between points.

### 2.1 One user source, one validation input

**The grid (User Manual pp. 8–9; CR-3813 App. E p. E-8).** k = 1…16 along the fuselage, ℓ = 1…10 around it from the propeller azimuth: x₁ = (r_p − a) + a(1 − cos α_ℓ), x₂ = −a sin α_ℓ, x₃ = (πa/18)(k_p − k), with α_ℓ = (ℓ − 1)·10°, and the fuselage station z_k = z_p − x₃ (z is the cabin axis, the aircraft body x axis, from the forward end of the cylinder). For the test article z_p = 0.662 m (App. E). Fixed 2026-10-23 (plan Phase 65): the code had z_k = z_p + x₃ with z_p = 0.90 m, a grid mirrored about the propeller plane.

The original PAIN took this grid from ANOPP. In this recreation the only user option is CCBlade + F1A (BEMT + F1A, for your own
propeller). NASA's measured Fig. E-11 line is not an option: it is the input of a validation test that checks the cabin model
against NASA's published results. No comparison with ANOPP is planned.

### 2.2 NASA measured data (validation test only)

Layout: [`METHODOLOGY_STRUCTURE.md`](METHODOLOGY_STRUCTURE.md).

**Validation chunk: NASA measured free field and the 160-point grid** (map groups *Free field* and the grid block of *Grid and
blocking*). This chunk is a validation test input, not a user option. No published source gives the measured field at all 160
points (only the ℓ = 1 line), so it is checked in pieces: the reading of the line, the unit conversions, the grid geometry, and,
as an importance bound only, the grid extension.

**What it does.**
- Fig. E-11 digitization (two independent readings) gives the measured free-field level on the ℓ = 1 line, H1–H3; ANOPP Table 8 supplies H3 and all phases.
- GEXT (assumed grid extension) fills the other 150 points with a cosine falloff in peripheral angle and a geometric phase delay.
- The 160-point grid (User Manual Fig. 3) fixes every observer, incidence angle γ and panel area.
- Source select hands this grid, or the aircraft grid of §2.3, to blocking.

**Claim today:** the digitized line is V-EXP for the repeatability of the reading only; GEXT is V-ASSUMED and unfalsifiable by
published data; the grid and conversions are V-UNIT. The detailed notes follow.

**Implementation notes and claims.**


1. **Digitized Fig. E-11.** The measured free-field line (l = 1) for harmonics H = 1, 2, 3, digitized twice; the two readings
   agree within δ_dig ≤ 1.0 dB. **Claim: V-EXP input, for the repeatability of the reading only.** H = 3 and all phases come
   from ANOPP Table 8, not from Fig. E-11, and measured H1/H2 are clipped to ANOPP where they exceed it (`broadband_clip_dB` 10).
   **I-17 (closed 2026-10-21 by Phase 37b; status corrected 2026-10-28):** `spl_dB_to_Pa` converts published dB to Pa as an rms-equivalent amplitude and feeds that into
   Eq. (42) as A; documentary reading of CR-3813 / User Manual / CR-172428 is that A is the Fourier cosine-peak amplitude
   (A = √2 p_rms). Omitting √2 left e11 / Table-8 tones ~3.01 dB low; fixed in Phase 37b (`spl_dB_to_peak_Pa` feeds Eq. (42)), every affected result re-recorded post-hoc.
2. **Grid extension (GEXT).** The paper measured one line, so the other points are filled with a cosine falloff in peripheral
   angle and a geometric phase delay from the path-length difference. **Claim: V-ASSUMED, unfalsifiable by published data.**
   On l = 1 the angle is 0 and the path length equals the reference, so the falloff is constant at 1 and the delay is 0 on the
   only measured line; neither can be fitted to, or checked against, it. No parameter is fitted; the form was fixed a priori
   (author attestation, not verifiable from the repository). The unit tests verify the code (falloff at 0°, 45°, 90°, phase
   sign, axis mapping), not the physics. GEXT is used in this path only.
3. **GEXT importance bound (planned, plan phase 32).** Varies the falloff exponent, a floor and the delay with every calibrated
   cabin parameter held fixed, and reports whether any variant flips the T1 verdict. It measures importance, not correctness and
   not circularity. The specification and the T1 claim-status table are in `VALIDATION_GUIDELINE.md` §2.2.1 and in §8 below.

### 2.3 Airfoil BEMT+F1A

Layout: [`METHODOLOGY_STRUCTURE.md`](METHODOLOGY_STRUCTURE.md).

**Validation chunk: Airfoil BEMT+F1A** (map group `G_AIR`, `VALIDATION_GUIDELINE.md` §2.13). The chunk is checked in pieces: no
published source runs through the whole chain (polars, loads, pressure, phase, forward flight), so each source below validates
one piece and the cases are grouped by the map check block they belong to.

**What it does.**
- Airfoil polars come from XFOIL, with a Viterna post-stall extension, and are combined with the blade dimensions.
- CCBlade (blade-element momentum, BEMT) computes the section lift and drag, hence the loads, along the blade.
- AcousticAnalogies (Farassat F1A) computes the free-field pressure time history at each observer; a DC-removed FFT gives the
  harmonic amplitudes and phases.

**Chain.** `Aircraft inputs (XFOIL polars, dimensions) -> CCBlade (BEMT) -> AcousticAnalogies (F1A) -> free-field p at the 160 points`

| Block (map id) | Inputs | Outputs |
|----------------|--------|---------|
| Aircraft inputs (`A_GEO`) | XFOIL section polars c_l, c_d (α, Re, M) with Viterna extension; blade chord, twist, thickness, hub and tip radius, blade count B; rpm, forward speed, air density and sound speed; propeller placement r_p, φ_p, z_p; the 160-point observer grid | One aircraft description for CCBlade and F1A (`polars.jl`, aircraft JSON) |
| CCBlade BEMT (`A_LOADS`) | The aircraft description | Section normal and tangential loads along the blade; thrust T, torque Q, C_T, C_P |
| AcousticAnalogies F1A (`X_F1A`) | Section loads and blade geometry, Ω, B, flight velocity, observer positions, sound speed, `thickness_over_chord` | Pressure time history p(t) at each observer; harmonic amplitude 2\|X\|/n and phase per harmonic |
| Free field p (`X_FF`) | F1A amplitude and phase at the 160 points | Handed to Source select (blocking and the cabin chain) and to the checks below |

**Implementation notes.** The default is loading-only (`thickness_over_chord = 0`); the experimental source comparisons (Report 996, Pereira) run with the thickness term on since Phase 76 (2026-10-28), with A/c² per station from the section coordinates (`report996_area_over_chord2`: shoelace area of the NACA 16 contours, A/(t·c) 0.72–0.84, blended in t/c like the polars; `naca4_area_over_chord2`: 0.68505·t for the NACA 4412). With it R996_FIG12, R996_FIG14 and PER_FIG7 are met; the loading-only runs missed most in the plane of rotation and at the higher harmonics, where thickness noise is strongest. `thickness_over_chord` enters F1A as the cross-section area / chord² (AcousticAnalogies' `area_per_chord2`), not as t/c; a NACA 16 section has A ≈ 0.72–0.78·t·c (measured on the Report 996 sections, 2026-10-28). A per-station `area_over_chord2` vector overrides it. CCBlade receives the air viscosity μ = 1.78·10⁻⁵ Pa·s (from 2026-10-28; before that CCBlade's default μ = 1 was used, see §2.4). `asound` must be passed as the sound speed
(CCBlade's default of 1.0 m/s breaks F1A). Observers use AcousticAnalogies' (x3, x1, x2) ordering with the User Manual
r_p = a + 0.457. In AcousticAnalogies the rotor travels along +X, so +X is ahead of the propeller (upstream) and the thrust points along +X; the aircraft grid maps x₃ (forward positive) to +X. The validation sources follow their own documents: Report 996 x/D is positive ahead (p. 6), so `R996_X_SIGN = +1`; Pereira's φ is positive downstream (Fig. 2b), so `pereira_observers` puts x = −r sin φ; Pereira's Fig. 7 phase fit is p = A cos(kBθ − ψ), so Δψ = −Δφ of our FFT phase (Phase 72, 2026-10-28; until then both validation scripts had the microphones on the wrong side of the plane). The aircraft path runs F1A at all 160 grid points through one shared source function
(`evaluate_propeller_source`), used by the production grid and by every validation case; GEXT stays on the e11 path only.
Source time span is two revolutions (`n_rev_src = 2`) with a reception-inside-elements guard (I-01); harmonic phase is
`angle(c) − ω_H·t₀` (I-02, fixed 2026-10-21). Optional Table-8 peak calibration is a post-step and is never compared with Table 8
when enabled (I-12/B-5). Raw smoke against Table 8 (untuned geometry): peak deltas −4.2/−5.3/−5.8 dB (X-EXTRAP). Display-only
cases `POLAR_R996` / `POLAR_PER` plot the polars, digitized TN 1546 / Report 824 section overlays (`data/airfoil_measured/`, not
read by BEMT) and where the section operating points sit relative to the polar grid (no criterion, no verdict).

**Validation sources.** Criteria are frozen in `VALIDATION_GUIDELINE.md` §2.12; the §2.3.1 and §2.3.2 rules (no tuning to these

**How the code reads them** (`load_polar_set`, `src/polars.jl`). *Until 2026-10-28:* one function c_l, c_d (α, Re, M) for every blade station, taken from the single nearest stored (Re, M) table with no interpolation; Re and M outside the grid clamped to the edge; linear in α inside a table and the end value held outside it. *From 2026-10-28 (Phase 69a):* tables keep their section and each blade station gets its own polar, linear in t/c between the two sections that bracket it (`section_polar`, `station_polars`; a multi-section set without station thicknesses is an error). Lookup is bilinear in (log Re, M), with Re and M clamped to the grid range and the clamps counted. With `cr75` each table is extended past its converged angles by the registered Viterna rule, and an unusable table is replaced by the nearest usable one of the same section. CCBlade now gets the air viscosity μ = 1.78·10⁻⁵ Pa·s. The `:bracket` set multiplies c_l by 0.92264 and c_d by 1.81815.

**Defects found in the 2026-10-28 audit** (fixed in Phase 69a; results re-recorded 2026-10-28, post-hoc: R996_LOADS 24/32 within ±15 %, was 6/32; R996_FIG12 28/40, was 21/40; Pereira thrust +0.7 % of measured, was −61 %; no case verdict changed, see `VALIDATION_GUIDELINE.md` §2.14).
1. The section name is dropped when the file is read, so every blade station uses the last section read, NACA 16-101 (1.3 % thick, design c_l 0.1). The Report 996 blade runs from about 13 % thick at the hub to about 5 % near the tip, with design c_l up to 0.5. Every Report 996 load and near-field result so far used this one section, so the Phase 67 attribution ("XFOIL input fidelity, not code") does not hold. Pereira has one section and is not affected.
2. There is no interpolation in Re or M (nearest table only). The tip stations at tip Mach 0.75 and 0.9 are read from M = 0.72.
3. Angles past the end of a table are held at the end value: no stall, and the Viterna extension in §2.10 of `VALIDATION_GUIDELINE.md` is not applied by this loader. The static Report 996 runs reach α = 20°–30°.
5. CCBlade is given no air viscosity (its default is μ = 1), so the Re sent to the polars is about 10⁵ too low (Report 996: 5–14; Pereira: 2–3). Every BEMT lookup so far used the lowest Re table: 3·10⁵ for Report 996 and 2·10⁴ for Pereira.
4. Report 996 and TN 1546 do not state that the blades or models were tripped, so the forced x_tr = 0.02 setting has no documentary basis. Pereira states natural transition (no tripping) and tunnel turbulence below 0.1 %, which N_crit 9 matches.

## 4. Stage 3: cabin acoustic modes (CYL2D)

### 6.2 PAIN main (coupling, Eq. 8, broadband)

**Validation chunk: PAIN main** (map group *PAIN main*). The core sums modal contributions into interior levels. NASA gives no
isolated intermediate values for it, so the chunk is checked by independent re-implementations and hand evaluations of each
helper; the whole-chain comparisons are 6.3.

**What it does.**
- Coupling f′ (Eq. 52 and its parts) and the generalized force Ψ_G (Eq. 42) turn the blocked field into modal forcing.
- Eq. (8) sums the cabin-mode pressures for the tones; the high-frequency expected value (Eqs. 11–16) replaces it where modes are dense.
- Reverberant noise reduction (Eqs. 17–18) and printed high-frequency broadband (Eqs. 19–23) give the band levels.

**Key equation.** Eq. (8), summed over the cabin modes by Eq. (3), in the form the code evaluates
(`tone_mean_square_pressure`):

$$\langle p^{2}\rangle_H \;=\; \sum_n \frac{4c_0^{2}}{V^{2}}\left(\frac{mA}{4}\right)^{\!2}\!\tau_{ML}\;\omega_H^{6}\,\frac{\varepsilon_n}{\omega_n^{4}}\;\sum_r \frac{\bar{f}^{\,\prime\,2}\,\Psi_G}{M_r^{2}\,\omega_r^{4}} \Bigg/ \Big\{\big[(1 - \omega_H^{2}/\omega_n^{2})^{2} + \eta_n^{2}\big]\big[(1 - \omega_H^{2}/\omega_r^{2})^{2} + (\eta_r' + \eta_r'')^{2}\big]\Big\}$$

with $(mA/4)^{2}\tau_{ML} = \big(\rho_0 c_0 A / (2\omega_H)\big)^{2}$, $A = L\,(L_p + 2a(\pi - \theta_0))$ the
transmitting area, and the generalized force of Eq. (42), $\Delta^{4} = \Delta A^{2}$:

$$\Psi_G(r, H) \;=\; \frac{\Delta^{4}}{2}\left[\Big(\sum A\,\psi\cos\varphi\Big)^{\!2} + \Big(\sum A\,\psi\sin\varphi\Big)^{\!2}\right]$$

## 10. What this recreation does not claim

- That F1A is better than Gutin, Hanson or ANOPP-style methods. The planned checks score CCBlade + F1A against measurement only;
  a "better" claim needs the other methods run on the same cases and data (`VALIDATION_GUIDELINE.md` §2.3.3).
- That T1 or T2 validate the cabin model or GEXT. Both are in-sample. Circularity is not measured; the GEXT bound is an
  importance bound only.
- That any GEXT or cabin result is free of refraction and scattering effects. Both stay V-ASSUMED, so every claim is
  conditional on them.
- Full Peterson shell-floor Fourier matrices: addressed in 38g by `mrp_appd.jl` (printed App. D); the calibrated `mrp.jl`
  surrogate still uses diagonal Donnell/Kirchhoff + junction springs and remains the non-default path only.
- CCBlade/F1A as a validated replacement for ANOPP. Source checks (BBN 24c, Report 996 23c, Pereira 23d) did not meet
  frozen §2.12 tolerances (2026-10-21). The optional Table-8 peak calibration is an X-EXTRAP post-step only and must never
  be compared with Table 8 when enabled (`anopp_table8_calibrate: false` for raw checks).
- T2 above 2 kHz: Figs. E-9 and E-10 end near 2 kHz, so there are no measured means for 2.5–8 kHz.
- The App. A multilayer transfer matrix against laboratory material coupons: the masses come from the App. E text and the insulation
  data from Fig. A-2 digitized at six frequencies (±1 % of full scale); the Phase III facing/septum loss factor, the G-10 wavespeed, the mechanical connections and the end-plate backing are V-ASSUMED (register f).
- Inheritance of NASA validation by the aircraft CCBlade path without a source check that supports it.
- That the GUI Validation tab is a place to tune cases. Cases are registered and read-only; changing inputs after a result exists makes that result post-hoc (CLAUDE.md / plan R2–R3).

## 11. Conditions that apply to every claim

- **Parameters fitted or chosen with a target in view** are listed in the parameter register (`VALIDATION_GUIDELINE.md` §2.10).
  Any result that depends on them is a consistency check, not an independent validation.
- **Rules for every comparison:** no tuning to the cases; fix settings and pass criteria before comparing (plan phase 23);
  calibrated checks are labelled as such.
- **Refraction and fuselage scattering and reflection** are V-ASSUMED and kept out of the falloff and source tests.

## 12. Preferred cabin path and code notes

Preferred cabin path (calibrated): `data/cr3813/e11_freefield_measured_A.csv` (with the ANOPP phase and H3 cleanup) -> GEXT -> blocking R2
-> Table D-1 hybrid MRP + CYL2D -> PAIN core with per-harmonic T(ω)/η and Eq. 19 high-frequency broadband -> T1/T2.

- Always pass `asound = c0` into `CCBlade.OperatingPoint` (the package default is 1.0 m/s).
- F1A observers are `[x3, x1, x2]` with `r_p = a + 0.457`.
- FFT: DC-removed, peak amplitude 2|X|/n, `df = 1/(n·dt)`.
- `extend_line_to_grid` has `falloff_exponent`, `falloff_floor` and `delay_scale` for the importance bound. The defaults are
  the nominal GEXT; they are not fitted parameters and must not be tuned to T1/T2.
