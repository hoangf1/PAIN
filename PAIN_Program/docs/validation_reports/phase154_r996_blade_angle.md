# Phase 154: the Report 996 blade angle from Report 996 Fig. 3(c) (2026-11-14)

Decided and done by Claude under the author's authority of 2026-11-14 ("do thats right", read as "do what's right" on the ISSUE-044 question). Generated by a script that was run once and not kept; the digitizer and the blade-input builder are kept (`data/digitizers/dig_r996_fig3c.py`, `build_r996_blade_fig3c.py`).

## What changed

- **Blade angle.** The Report 996 cases now take it from their own report's Fig. 3(c), read by script (`measured/geometry/tr996_fig3c_blade_form.csv`; passes A and B differ by at most 0.12 deg in beta, 0.0011 in h/b, 0.0027 in b/D (delta_dig, without the flagged pass-B readings); one pixel is 0.016 deg of beta. beta_deg is pass A). The new input is `blade_form_r996_fig3c.csv`: the table's stations, chord, thickness and design lift, and the table's blade angle corrected to Fig. 3(c) at its gridlines.

- **Code.** `blade_form_geometry` takes the 0.75 R design angle from the file it reads, instead of the fixed 42.64° (the table's value, so its results are unchanged); a unit test checks it.

- **Not changed.** The CR-196702 table (`blade_form.csv`), every criterion, tolerance and measured file, and the blade root (r/R 0.271: no document in `references/` prints the static rig's spinner). Chord and thickness stay the table's: its width ratio at 0.7 R, 0.0659, is the designation's solidity 0.03, and Fig. 3(c) reads about 1 % lower.

**Labels.** Every result below is a re-run after the earlier results were known: post-hoc. The change was found on Report 1012's data (ISSUE-043), not on any of these cases' own compared data, so the independence rule does not apply; nothing was chosen from these residuals.
